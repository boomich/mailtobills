MailToBills UX exploration

Review expense documents in a right-side drawer.

Replace the current external PDF navigation with an in-app drawer that slides over the dashboard, exposes email context, and embeds the selected Primary Attachment PDF — so the user never loses their place in the month.

Recommended direction (decided)

Use a right-side overlay drawer for the selected Collected Expense Document — the Asana / ClickUp task-detail pattern: the drawer slides in from the right edge over a dimming scrim, the dashboard stays mounted behind it, and clicking the scrim or pressing Escape returns the user to the table.

Build it on the existing Sheet component (side="right", with backdrop). The row action selects the row, opens the drawer, and renders the authenticated file route inside an embedded viewer.

Product behavior

  • Clicking a row or View selects the row and opens the right-side drawer instead of navigating to a new tab.
  • The drawer overlays the dashboard with a dimming scrim. The dashboard stays mounted behind it; the selected row stays highlighted underneath.
  • Closing (scrim click, Escape, or ✕) returns the user to the same scroll position in the table.
  • Previous / next pager moves through the month's documents without closing the drawer.
  • The drawer switches between attachments in the same Attachment Set without closing.
  • Keep a download action for users who need the raw PDF file.

Data already available

  • ExpenseDocumentRow.primaryAttachment gives the default PDF.
  • attachments supports alternate PDFs and Primary Attachment changes.
  • originFromEmail, originFromName, originSubject, and originSentAt provide richer email detail than the row can show.
  • downloadUrl already points to the authenticated Next route.

Component shape

  • Add expense-document-detail-panel.tsx inside apps/dashboard/features/expense-documents/components.
  • Build on the existing Sheet component with side="right" and a backdrop; override width to min(92vw, 720px).
  • Keep selection state in ExpenseDocumentsTable: selected document id plus selected attachment id. Derive the pager index from the current filtered row list.
  • Turn ViewPdfButton into a button callback, not an anchor. Make the whole row clickable too.

PDF viewer approach

  1. First pass: embed /api/files/[attachmentId] with an iframe or object type="application/pdf". This keeps auth and routing simple. No custom zoom chrome in this pass — the browser's native PDF viewer owns zoom/page controls. The toolbar carries only the filename and an "Open original" link.
  2. Always render an "Open original ↗" link to the file route as a fallback. iOS Safari and some in-app browsers refuse to render PDFs inside iframe/object and will need it.
  3. Set the file route response to stay inline and keep cache-control: private, which it already does.
  4. Later pass, only if needed: introduce a dedicated viewer library (e.g. pdf.js) for in-app zoom, thumbnails, page navigation, and consistent cross-browser controls. Custom zoom UI belongs here, not in pass one.

States to design

  • Loading: skeleton in the PDF frame while the embed loads.
  • Render failure: if the embed can't display (mobile Safari, blocked plugin), show "Can't preview this PDF here" with the "Open original" and "Download" actions.
  • Auth / 404: handle a failed file route gracefully rather than a broken frame.
  • Single attachment: hide the attachment strip when there is only one file.

Destructive actions

  • Keep Delete out of the primary action row. Put it behind the ⋯ overflow menu in the header.
  • Require a confirmation step (dialog) before deleting; deletion is irreversible.
  • After delete, advance the drawer to the next document (or close if it was the last).

Accessibility and keyboard

  • The drawer is a modal dialog: trap focus, close with Escape, and restore focus to the triggering row action on close.
  • Move focus to the drawer heading (or close button) on open; mark the scrim aria-hidden.
  • Rows expose selected state with aria-selected while the drawer is open.
  • Every control is a real button — close, pager, overflow, and attachment cards — with explicit names like "Preview terms.pdf" and "Make terms.pdf primary".
  • Pager and attachment switching announce the change (live region or focus move) for screen readers.

Responsive

  • Desktop: drawer is min(92vw, 720px) over a scrim; dashboard visible behind.
  • Mobile: drawer becomes a full-screen sheet. The pager and ✕ are the way back to the list, so keep both reachable at the top.
  • Collapse "Email details" by default on small screens so the PDF is above the fold.

Implementation sequence

  1. Create the detail drawer component (Sheet, side="right", backdrop) with: header + pager, collapsible email-detail section, PDF frame with loading/error states, attachment strip, and Download / Make primary actions plus an overflow menu housing Delete.
  2. Update ExpenseDocumentsTable to store drawer state (selected document id, selected attachment id), expose the row list for the pager, and pass mutation handlers into the drawer.
  3. Replace external PDF links in row and expanded attachment actions with drawer-opening buttons; make the row body clickable.
  4. Add dashboard component tests covering "View opens the drawer", "scrim/Escape closes and restores focus", "pager moves to next document", "attachment switch changes iframe src", "download link remains available", "Delete is behind the overflow menu and confirms", and "Make primary still calls the Convex mutation".
  5. Update docs/launch-validation-checklist.md so validation checks say "open the in-app drawer" instead of only opening the raw PDF link.
